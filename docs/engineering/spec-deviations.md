# Spec deviations register

This register lists every requirement, hypothesis and question of the French specs in `docs/` that a [decision record](../adr/README.md) changes, extends or settles. Check it before implementing or reviewing a requirement: when its ID is here, the "What we do instead" column and the record apply; when it is not, the French text applies. The closing section, "Read this before implementing", gives the precedence rules.

Kinds:

- **overridden**: the spec text is replaced.
- **exception**: the spec text stands, except in the bounded case described.
- **extended**: the spec text stands, with the additions described.
- **settled**: an open question, a hypothesis to confirm or an option the spec left open is decided; the row names the default that now binds.

IDs are quoted as the specs write them. Acceptance criteria that a spec lists without an ID are cited by document and position, for example `12 AC-8` for the eighth criterion of document 12, in the row of the requirement they test. Record numbers refer to the files `docs/adr/NNNN-*.md`. French labels stay in « guillemets »; their English form comes from `docs/engineering/glossary.md`.

## Readings applied

Where a decision's wording left room, the rows above apply these readings. The orchestrator may overturn any of them by amending the record.

- Paris time is the default time zone, and the time-zone setting of IHM-14 stays ([0010](../adr/0010-english-product.md)).
- English number format: decimal point, comma for thousands ([0010](../adr/0010-english-product.md)).
- The developer level covers the deployment guide, TRV-77 and the operations guide; in-app help, the guided start and empty states still assume no technical knowledge ([0014](../adr/0014-developer-level-deployment-guide.md)).
- Calendar derivation runs for active and paused players, the players who may still receive a backtest ([0015](../adr/0015-calendar-derived-event-types.md)).
- Calendar-derived events never take part in duplicate matching ([0015](../adr/0015-calendar-derived-event-types.md)).
- The doubtful-criterion switch names at most one automatic criterion and creates no new sheet version ([0016](../adr/0016-per-type-doubtful-criterion-switch.md)).

## Read this before implementing

1. **Precedence.** For an ID listed in this register, the "What we do instead" column and its record override the French text — and the decision journal too, which otherwise prevails over the other spec documents. Everywhere else the French spec is authoritative, including every hypothesis marked « à confirmer », which is implemented as written.
2. **Language.** The specs quote French labels, states, messages and examples throughout. Render each with the English term of `docs/engineering/glossary.md`. Only the requirements that prescribe French are listed here; translating a quoted label never changes behavior.
3. **Open points.** Never settle one inside a pull request. Raise it with the orchestrator; the answer is recorded before the affected requirement is implemented.
4. **Tests.** A test of an acceptance criterion changed here asserts the value given here and cites both the criterion and the record.
5. **Changes.** The French specs are frozen. A new deviation needs a record and a row here, in the same pull request as the code that relies on it, or earlier.
